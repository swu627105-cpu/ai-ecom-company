# 第 0 章 先建立直觉：这个项目是一家"公司"

不要一上来就看代码。先想一家真实的公司怎么运转：

| 现实中的公司 | 这个项目里的对应物 | 专业名词 |
| --- | --- | --- |
| 前台、办公室、你看得见的一切 | 你在浏览器里点来点去的界面 | **前端 / Frontend** |
| 后厨、仓库、财务室，你看不见但在干活 | 处理数据、调模型、存文件的那部分 | **后端 / Backend** |
| 外聘的咨询顾问，按小时收费 | 书生大模型（写方案、做判断） | **LLM / 大模型 / 模型** |
| 档案柜 | `state.json`、`settings.json` 这些文件 | **持久化 / 存储** |
| 公司规章："超过 5 万必须老板签字" | 代码里的校验、风控、审批门槛 | **业务规则 / 校验** |

一句话概括整个项目：

> **前端负责"好看和能点"，后端负责"算得对、存得住"，模型负责"想得出"，文件负责"忘不掉"。**

这个项目最值得学的地方，是它把"AI 说话"和"AI 干活"分开了：模型只负责出方案，真正改数据的是一次次被记录、被校验、可回滚的**工具调用**。这个设计思想比代码本身值钱。

# 第 1 章 零基础概念课（16 节，看懂代码的前提）

每节都按「是什么 → 打个比方 → 在这个项目里是哪块」来讲。

## 1.1 文件夹、路径、绝对路径

- **路径**就是地址。`D:\桌面\AI 公司\platform` 是**绝对路径**（从盘符开始的完整地址）。
- `../docs` 是**相对路径**（相对于"我现在在哪"）。`..` 表示上一层。
- 代码里大量出现 `path.resolve(__dirname, '../..')`，意思就是"从我这个文件所在目录往上跳两级"。

**为什么重要**：百分之八十的"文件找不到"错误，都是路径写错或"我现在在哪个目录"搞错了。

## 1.2 前端 和 后端，到底谁是谁

|  | 前端 | 后端 |
| --- | --- | --- |
| 跑在哪 | 用户的浏览器 / Electron 窗口 | 本机的一个 Python 进程 |
| 语言 | TypeScript（长得像 JavaScript） | Python |
| 管什么 | 显示、点击、动画 | 数据校验、调模型、读写文件 |
| 能不能碰硬盘 | **不能**（浏览器安全限制） | 能 |
| 崩了会怎样 | 页面白屏 | 页面还在，但所有按钮报错 |

前端想存东西、想算账，必须**发请求**给后端。这条"请求"的路，就是下一节的 API。

## 1.3 HTML / CSS / JavaScript：网页三件套

- **HTML** = 骨架。`<div>盒子</div>`、`<button>按钮</button>`。
- **CSS** = 皮肤。颜色、大小、间距。
- **JavaScript**（简称 JS）= 肌肉。点击之后发生什么。

本项目的 `apps/web/index.html` 只有 15 行，它做的事就一件：放一个空的 `<div id="root"></div>`，然后把 JS 引进来，让 JS 往这个空盒子里"画"整个界面。

## 1.4 TypeScript：给 JS 加了"类型检查"

JS 太自由，`"5" + 1` 会得到 `"51"` 而不是 6，很容易出错。TypeScript（TS）就是你写代码时先声明"这个变量是数字"，写错了编辑器立刻红线警告。

- 文件后缀 `.ts` / `.tsx`（`.tsx` = 里面写界面）。
- 浏览器**不认识** TS，所以要用工具先"翻译"成 JS。这个翻译叫**编译/构建**。

本项目 `apps/web/src/api.ts` 里有一大堆 `type ApiApproval = {...}`，那不是逻辑，那是**数据长什么样的说明书**。它让你在写 `a.title` 时，编辑器知道有 `title` 这个字段。

## 1.5 React：把界面拆成"零件"

传统写法是"改页面上的某个字"，你得先找到那个 DOM 节点再改。React 换了个思路：

> **你只描述"数据是什么样，界面就该是什么样"，数据一变，React 自动帮你重画。**

- 一个"零件"叫**组件（Component）**，本质是一个返回界面的函数。
- 数据叫**状态（state）**，用 `useState` 声明。
- `useState` 给你两样东西：当前值 + 一个只能通过它改值的函数。**你不能直接改变量，必须调那个函数**，否则界面不会更新。

```tsx
const [tab, setTab] = useState('feed');   // 当前标签页，初始是"公司频道"
setTab('tasks');                          // 改成"任务"，界面自动重画
```

这就是本项目 `App.tsx` 里那几十行 `useState` 的全部含义——它们在记录"现在选中哪个标签""有几条审批""连没连上后端"。

## 1.6 Node.js 和 npm：前端世界的"发动机 + 应用商店"

- **Node.js**：让 JavaScript 能脱离浏览器、直接在电脑上跑的程序。Vite、TypeScript 编译器、Electron 都靠它跑。
- **npm**：Node 的包管理器。别人写好的代码包（叫"依赖 / dependency"）用一条命令下载。
- `package.json` = 这个项目的"购物清单 + 说明书"：我叫什么、版本多少、依赖哪些包、`npm run xxx` 分别执行什么。

本项目的 `package.json` 里有：

```json
"scripts": {
  "dev": "npm run dev -w @aiecom/web",     // 启动开发服务器
  "build": "npm run build -w @aiecom/web", // 编译出可部署的静态文件
  "desktop": "npm run start -w @aiecom/desktop"
}
```

`-w @aiecom/web` 里的 `-w` 是 workspace（工作区），意思是"去子项目 web 里执行这个命令"。这是个**多包仓库**：一个根目录管着 web（界面）、desktop（桌面壳）两个子项目。

- `npm ci` 和 `npm install` 的区别：`ci` 严格照 `package-lock.json` 装，一个版本都不许偏，适合"照原样复现"；`install` 可能会升级小版本。项目里用 `ci` 是为了**可复现**。

## 1.7 Vite：开发时的"即时预览器"，发布时的"打包机"

- `npm run dev` → Vite 起一个本地服务器（本项目是 `localhost:5173`）。你改代码，浏览器**自动刷新**，这叫热更新。
- `npm run build` → 把几十个 `.tsx` 文件压缩合并成几个 `.js` + `.css`，输出到 `apps/web/dist/`。这个 `dist` 就是可以直接丢给任何人打开的"成品"。

**记住这条**：`src/` 是原料，`dist/` 是成品。改代码要改 `src`，改完必须重新 `build`，`dist` 才会变。很多人改了代码发现页面没变，就是因为只改了原料没重新出厂。

## 1.8 Python、pip、venv：后端的"发动机 + 应用商店 + 独立房间"

- **Python**：后端语言。文件后缀 `.py`。
- **pip**：Python 的包管理器，对应 npm。`requirements.txt` 是购物清单：

```
fastapi==0.115.6      # 写接口的框架
uvicorn==0.34.0       # 把接口跑起来的服务器
pydantic==2.10.4      # 检查数据格式
httpx==0.28.1         # 发 HTTP 请求（用来调模型）
langgraph==1.2.18     # 把多步骤流程串起来
```

- **venv（虚拟环境）**：给这个项目单独开一间房，装的包只在这间房里生效，不污染系统 Python。本项目在 `apps/api/.venv/`。
  - Windows 里它的 Python 在 `.venv\Scripts\python.exe`；macOS/Linux 在 `.venv/bin/python`。
  - 所以你会看到 `apps/api/.venv/bin/python -m pip install -r requirements.txt` 这种长命令——就是"用这间房里的 Python，装这份清单上的包"。

## 1.9 HTTP、API、JSON：服务员、菜单、订单

这是**最关键**的一节。

- **API（接口）**：后端对外提供的"服务窗口"，每个窗口有个地址。
- **HTTP 方法**：动作类型。
  - `GET` = 我要看（不改东西）
  - `POST` = 我要创建 / 我要触发一件事
  - `PUT` = 我要整体更新
  - `DELETE` = 我要删
- **JSON**：前后端传输数据的标准格式，长这样：

```json
{ "id": "AP-1041", "title": "收纳柜预售价 429 → 369", "risk": "red", "status": "pending" }
```

就是"键: 值"的嵌套结构，人也能读。

**类比**：你去餐厅。
- 菜单 = API 文档（有哪些窗口）。
- 你说"来一份宫保鸡丁" = 发一个 `POST /api/orders`，附带 JSON 订单。
- 后厨做菜 = 后端处理。
- 端上来 = 返回 JSON 结果。

本项目所有接口都以 `/api` 开头，例如：

| 方法 + 地址 | 干什么 |
| --- | --- |
| `GET /health` | 体检：你活着吗 |
| `GET /api/approvals` | 拉审批列表 |
| `POST /api/approvals/{id}/decide` | 批准或驳回某条 |
| `POST /api/demo/runs` | 启动一次经营救援 |
| `GET /api/demo/runs/{id}` | 查这轮救援到哪一步了 |

## 1.10 端口：一台电脑上的"门牌号"

`127.0.0.1` 表示"本机"，`:8000` 是端口。就像同一栋楼里的不同房间号。

- 前端开发服务器：**5173**
- 后端 API：**8000**
- 桌面版：**随机端口**（因为要避免和你已经开着的开发版撞车）

`http://localhost:8000` = 本机 8000 号房间。看到"端口被占用"，就是这间房已经有别人住了。

## 1.11 跨域（CORS）：浏览器的一道门禁

浏览器有个安全规则：`localhost:5173` 的页面，默认不许直接找 `localhost:8000` 要数据，因为"门牌号不同"。解决方法是后端明确声明"我允许这几个来源访问"。

项目里这段就是干这个的：

```python
app.add_middleware(CORSMiddleware, allow_origins=[
    "http://localhost:5173", "http://127.0.0.1:5173", ...])
```

**如果你改了前端端口却没改这里**，页面就会报 CORS 错误，一个数据都拿不到。

## 1.12 环境变量与 `.env`

有些东西不能写死在代码里（尤其是密钥）。做法是放在**环境变量**里，代码运行时去读。

- `.env` 文件就是"一串 KEY=VALUE"的本地配置。
- `.env.example` 是模板（可以提交到仓库），`.env` 是真身（绝不能提交）。
- 项目 `.gitignore` 里明确排除了 `.env` 和 `apps/api/data/`，就是防止密钥和你的运行数据被传出去。

## 1.13 Electron：把网页塞进一个 exe

浏览器打开网页，地址栏、标签页都是浏览器的。Electron 干的事是：**自带一个浏览器内核，只显示你的页面**，于是"网页"就变成了"桌面软件"。

它的结构很固定：

| 文件 | 角色 | 干什么 |
| --- | --- | --- |
| `main.cjs` | 主进程（幕后老板） | 开窗口、管进程、系统菜单 |
| `preload.cjs` | 保安 | 只把允许的能力递给网页，别的都不给 |
| `backend.cjs` | 保姆 | 负责把 Python 后端拉起来、等着它活过来、关窗时收尸 |

注意后缀 `.cjs`：表示"这是老式 CommonJS 写法的 JS"，和前端 `.ts` 不是一回事。

## 1.14 异步（async / await）：别堵在门口等

调模型要等 20 秒。如果代码"等到结果再干下一件事"，这 20 秒整个程序就卡死了。异步的意思是：**发出请求后先去干别的，结果回来再接着处理**。

```python
await llm.chat(...)      # 等模型，但不阻塞别人
```

你会看到到处都是 `async` / `await`，它们就是"这里要等，但别把整个程序卡住"的标记。

## 1.15 轮询（polling）：前端怎么知道进度

后端跑一个流程要几十秒，前端不可能一直连着。最简单可靠的办法是**每隔一会儿问一次**："好了吗？到哪步了？"

本项目就是用这个：
- 任务列表每 **1.5 秒**问一次 `/api/tasks`；
- 救援流程每 **0.9 秒**问一次 `/api/demo/runs/{id}`。

这就是你在界面上看到进度条自己往前爬的原因——不是后端推送，是前端在敲门。

## 1.16 LangGraph：把流程画成"节点 + 箭头"

一个流程如果只是"调模型→执行"，用 if 就行。但这个项目要做的是：

> 感知 → 规划 → 风控复核 → 人工审批（会停下来等） → 执行 → 校验

中间还要能暂停、能回滚、能重跑某一版。这种"有状态的多步骤流程"，用 LangGraph 表达最清楚：每个环节是一个**节点（node）**，节点之间连**边（edge）**，整体状态存在一个共享的字典里。

**但要看清边界**：本项目用的是 LangGraph 的图结构，审批和检查点这些"持久化"是自己用 JSON 文件做的，**不是** LangGraph 官方的分布式 checkpointer。答辩时别说错。

## 一张表：哪些要管，哪些别管

| 路径 | 是什么 | 你要不要动 |
| --- | --- | --- |

# 第 3 章 后端详解（`apps/api`）

后端有 12 个 Python 文件（其中 `__init__.py` 是空的，只用来标记"这是一个包"），但真正需要理解的只有 **6 个**。按"从下往上"的顺序看最省力：**数据长什么样 → 存在哪 → 怎么执行 → 怎么调模型 → 接口怎么暴露 → 主流程怎么串**。

## 3.1 `paths.py`（6 行，但决定数据存哪）

```python
API_ROOT = Path(__file__).resolve().parent.parent     # 往上一级：apps/api
DATA_DIR = Path(os.environ.get("AIECOM_DATA_DIR", str(API_ROOT / "data"))).expanduser().resolve()
```

翻译：**如果环境变量 `AIECOM_DATA_DIR` 有值就用它，否则用 `apps/api/data`。**

这一行就是"开发版数据"和"桌面版数据"分开的开关：
- 源码浏览器版：不设这个变量 → 数据落在 `platform/apps/api/data/`
- 桌面版：`desktop_entry.py` 把它设成 `%APPDATA%\AI-Ecom-Company\data` → 数据落在用户目录

## 3.2 `domain.py`：所有数据的"形状定义"

这里定义了审批卡、任务、会议、事件、审计记录各自有哪些字段。用 Pydantic 的 `BaseModel`，好处是**写错字段名或类型会立刻报错**，而不是悄悄存了个脏数据。

核心的几个：

```python
class Evidence(BaseModel):       # 审批卡的"决策依据"，六段
    summary: str                 # 结论
    metrics: list[str]           # 数据
    reasons: list[str]           # 理由
    risks: list[str]             # 风险
    rollback: str                # 回滚方式
    sources: list[str]           # 出处

class Approval(BaseModel):       # 一张待拍板的卡片
    id: str
    title: str
    from_: str = Field(alias="from")   # 谁提的
    risk: str                    # red / mid / low
    status: str                  # pending / approved / rejected
    evidence: Evidence           # 上面那六段
    ...
```

`alias="from"` 是个小技巧：Python 里 `from` 是关键字，不能当变量名，所以内部叫 `from_`，但输出 JSON 时仍叫 `from`（前端只认 `from`）。

还有几个工具函数：
- `new_id("AP")` → 生成 `AP-xxxxxx` 这种带前缀的编号
- `now_hm()` → 返回 `14:32` 这样的时分
- `reveal_next(m)` → 会议"推进一句"（会议是个状态机，每次只吐一句，这样测试和前端都好处理）

## 3.3 `store.py`：存档与读档（最值得学的 30 行）

整个系统就靠这一个类管理所有数据。启动时读一次，改动后存一次。

```python
def __init__(self, persist=True):
    seed = json.loads(SEED.read_text(encoding="utf-8"))   # 读"剧本"
    self.agents = [Agent(**a) for a in seed["agents"]]    # 造出 12 个员工对象
    ...
    if self.persist and DATA.exists():
        self._load()                                      # 有存档就读回来
```

`seed.json` 是"初始剧本"（员工性格、会议模板），`state.json` 是"你玩到哪了"。**剧本 + 存档 = 当前状态**，这是几乎所有游戏和业务系统的通用模式。

**存档那段用了三个容易被忽略的技巧**：

```python
with tempfile.NamedTemporaryFile(dir=DATA.parent, delete=False) as f:
    json.dump(payload, f); f.flush(); os.fsync(f.fileno())   # 1. 先写临时文件，并强制刷到磁盘
os.replace(temporary, DATA)                                  # 2. 再原子替换
```

1. **先写临时文件**：万一写到一半断电，坏的是临时文件，原存档还在。
2. **`fsync`**：告诉操作系统"别偷懒，真的写到硬盘上"。不做这步，断电可能丢最后一段。
3. **`os.replace`**：这是原子操作——要么换成功，要么没换，不存在"换了一半"。

**如果直接 `open(存档).write(...)` 会怎样？** 断电后你会得到一个被截断的、打不开的 JSON，所有历史数据全废。这就是为什么值得多写这 10 行。

审计日志用**哈希链**：

```python
prev = self.audit[-1].hash if self.audit else "genesis"
digest = sha256(f"{prev}|{seq}|{actor}|{action}|{target}|{at}").hexdigest()[:12]
```

每条记录的哈希里都掺了上一条的哈希。**如果有人偷偷改了第 5 条，第 6 条开始的所有哈希都对不上了**。这叫"防篡改"，但注意：它是本地链，不是第三方公证，对外只能讲"能发现是否被改过"，不能讲"有法律效力"。

## 3.4 `tools.py`：把"批准"变成"执行"（93 行，思想很妙）

这个文件回答一个问题：**点了"通过"之后，那些执行步骤是怎么动起来的？**

```python
STEP_SECONDS = 1.1        # 每一步"假装"耗时 1.1 秒

PLANS = [                 # 用正则匹配标题，决定这类事该分成哪几步
    (re.compile(r"价|折扣|促销|预售"), "price",
     ["校验库存与价格锁定", "生成改价快照", "模拟提交店铺平台", "校验前台价与价保规则"]),
    (re.compile(r"补货|采购|库存|备货|交期"), "stock", [...]),
    ...
]
```

**关键在 `refresh()`**：

```python
elapsed = now - task.created_ts          # 从创建到现在过了多久
done = int(elapsed / STEP_SECONDS)       # 过了几个 1.1 秒
```

它**根本不"执行"任何东西**，只是根据"过了多少秒"反推"该显示第几步了"。所以你看到进度条稳步前进，其实是时间的函数。

**为什么可以这么偷懒？** 因为这个版本是演示，不接真实店铺。但注意文件开头的注释：

> 接店铺接口时，把 `refresh()` 换成真实的工具调用即可，上层（审批、任务、事件、审计）不用改。

这就是**分层**的价值：把"假装"的部分集中在一个文件里，将来换成"真的"只改这一处。你在答辩时如果被问"这是真的执行吗"，标准回答就是：**跨岗的库存/预算/工单是真改沙箱数据的（在 `competition.py` 里），这里的通用提案是时间推进的步骤演示，代码里明确标注了。**

## 3.5 `llm.py`：模型网关（所有调模型都从这里出去）

这是整个项目最"工程化"的文件，解决四个现实问题。

### 问题一：配置放哪？

优先级从高到低：

```python
cfg = 默认值
if settings.json 存在: 覆盖         # 界面里填的，最高优先
if .env 有值: 覆盖                  # 部署时配的
```

**为什么**：评委在界面里填的 Key 必须能盖过开发者留在 `.env` 里的东西；而 `.env` 又不该被提交。三层优先级让"开发、交付、现场演示"三种场景都不打架。

### 问题二：密钥不能泄露

```python
def current():
    key = _cfg["api_key"]
    hint = f"{key[:3]}…{key[-4:]}" if len(key) > 8 else ""
    return {"base_url": ..., "model": ..., "key_hint": hint, "has_key": bool(key)}
```

接口只返回 `sk-…abcd` 这种打码后的提示，**永远不返回明文**。所以前端那个输入框在保存后是空的，提示"留空表示不修改"。

### 问题三：模型会抽风，不能把会议卡死

```python
quick_ready()      # 如果上次探测就没连通，这次直接走兜底，不再白等 60 秒
```

```python
try:
    answer = await llm.chat(...)
except Exception:
    answer = "模型暂时未返回。现有依据：" + evidence.summary
```

**这是产品级思维**：模型是外部依赖，一定会失败。失败时的体验决定这个系统能不能拿去演示。所以每一处调模型都有兜底，兜底会**明确标注"未调用模型"**，不假装是模型的结果。

### 问题四：模型返回的不是 JSON 怎么办

模型经常这样回：

```
好的，以下是分析结果：
```json
{"headline": "...", "findings": [...]}
```
```

`main.py` 里的 `_parse_json()` 专门治这个：先剥掉 ```` ```json ```` 这层壳，再找第一个 `{` 和最后一个 `}` 截出来。解析失败就返回 `None`，上层回落规则。

`_shape()` 再检查**结构是否合格**：没有 headline、发现少于 2 条、没有动作 → 判定不合格，也回落。这叫"**校验模型输出**"，是把 AI 当不可靠输入源来对待，而不是当神谕。

## 3.6 `competition.py`：经营救援主流程（773 行，项目的心脏）

这个文件分四层，从上往下读。

### 第一层：输入校验（Pydantic）

```python
class ServiceInput(BaseModel):
    orders: int = Field(gt=0, le=10000000)
    ...
    @model_validator(mode="after")
    def consistent(self):
        if not self.damaged_orders <= self.refund_orders <= self.orders:
            raise ValueError("必须满足破损单数 ≤ 退款单数 ≤ 总订单数")
```

**为什么要在后端校验，前端不是已经限制了吗？** 因为前端可以被绕过（改 JSON、调接口）。**校验必须在数据进门的地方做一次**，这是安全常识。

### 第二层：确定性计算（不调模型）

```python
def metrics(data): ...        # 算库存覆盖天数、加权 ROI、退款率
def rule_plan(data): ...      # 规则版方案：库存不足就调拨、ROI 低就迁预算
def decision_context(data): ...  # 把"最少要调多少、最多能调多少、够不够"算清楚给模型看
```

**注意 `rule_plan` 的定位**：它不是"模型的备胎伪装"，它是**公开的、可复现的基线**。评测时拿它当对照组，答辩时明说"规则策略，未调用模型"。

把计算交给代码、不交给模型，是这套系统靠谱的根本原因——模型会算错 240÷60，代码不会。

### 第三层：三个工具（真改沙箱数据）

```python
def execute_tool(action, data, run_id):
    if action["tool"] == "inventory.transfer":      # 调拨库存
        ...扣库存额度、扣现金、累计调拨费
    elif action["tool"] == "ads.rebalance":         # 迁移广告预算
        ...从拉新挪到复购，总额不变
    elif action["tool"] == "service.create_tickets":# 创建售后工单
        ...给未建单的破损单补工单
```

`validate_action()` 在执行前再卡一道：数量是否超过备用仓、是否超过可用现金、迁移金额是否超上限（900 元）。**模型说"调 5000 件"，代码会拦住**。

### 第四层：六个节点串成流程

```python
async def sense(...)    # 感知：算出当前指标，记一条 trace
async def plan(...)     # 规划：调模型（或走规则），产出方案
async def review(...)   # 复核：调模型独立审一遍方案，判断 safe / 不安全
async def gate(...)     # 闸门：生成审批卡，状态挂起等待人工
async def execute(...)  # 执行：逐个调工具，写回执
async def verify(...)   # 校验：对比执行前后，逐项检查约束
```

`gate` 是**整个设计的关键**：流程在这里**真的停下来**，把状态写成 `awaiting_approval`，等人点按钮。所以"人工审批"不是一句口号，是一个卡在代码里的中断点。

`DemoService` 还有几个能力值得知道：
- `revise()` 退回修改 → 版本号 +1，旧方案进 `versions` 数组，新版本重新过模型和风控
- `resume()` 从检查点继续（靠 `cursor` 游标，避免重复执行已完成的工具）
- `rollback_run()` 用 `before` 快照整体覆盖 `current`
- `public()` 对外输出时补上 `before_metrics` / `current_metrics`，前端就不用自己算

# 第 4 章 前端详解（`apps/web`）

## 4.1 从 `index.html` 到界面出现：只要三步

```html
<div id="root"></div>
<script type="module" src="/src/main.tsx"></script>
```

1. 页面加载，有一个空盒子 `#root`。
2. 浏览器去执行 `main.tsx`。
3. `main.tsx` 把 `<App />` 塞进那个空盒子。

`main.tsx` 只有 6 行，但有句注释很关键：

```tsx
// 会议状态机在服务端推进，这里不开 StrictMode，避免开发环境重复挂载导致 /next 被调两次
```

React 开发模式下 `StrictMode` 会把组件挂载两次（用来帮你发现副作用 bug）。但这个项目的会议推进是**有副作用**的（每调一次 `/next` 就吐一句台词），挂载两次就吐两句。**这是一个非常典型的"框架特性 vs 业务需求"冲突，注释把原因写清楚了，这就是好代码的样子。**

## 4.2 `api.ts`：所有"打给后端的电话"都在这

这是前端唯一允许直接 `fetch` 的地方。别的地方要数据，都从这里调。

```ts
export const API_BASE =
  import.meta.env.VITE_API_BASE ??                          // 1. 构建时注入的地址
  (window.desktop?.isDesktop ? window.desktop.apiBase        // 2. 桌面版：随机端口
                            : 'http://localhost:8000');      // 3. 开发版：固定 8000
```

**三行代码解决三种运行环境**。桌面版端口是随机的，所以必须由 Electron 通过 `preload` 告诉页面"后端在哪个端口"——这就是 `apiBase` 的来历。

探活函数：

```ts
export async function probe(): Promise<boolean> {
  const c = new AbortController();
  const t = setTimeout(() => c.abort(), 1500);      // 1.5 秒还没回，就放弃
  const r = await fetch(`${API_BASE}/health`, { signal: c.signal });
  return r.ok;
}
```

`AbortController` 就是"超时自动挂断"。**为什么必须设超时**：如果不设，后端没起时这个请求会挂几十秒，界面就一直卡在"加载中"。设 1.5 秒，失败得干脆，才能立刻切到"本地演练"模式。

下面每个函数对应一个接口，`json<T>()` 负责"如果状态码不是 2xx 就抛错，是就把响应体当 JSON 解析"。

`demoApi` 那一组是经营救援的 8 个接口：`template`（拿模板和 5 个案例）、`start`（启动）、`read`（查进度）、`approve`、`rollback`、`revise`、`resume`、`feedback`、`export`。**看这一组就知道整个救援流程有哪些动作**，比看界面还快。

## 4.3 `App.tsx`：主界面（563 行，一次看懂结构）

按顺序是四块：

**① 常量与假数据**（1–67 行）
`SEED_APPROVALS`、`SEED_EVENTS`、`DASH_FALLBACK`——后端没连上时页面不至于空着。`RISK_LABEL` 把 `red/mid/low` 翻译成"高风险/中风险/低风险"。

**② 状态**（69–88 行）
约 20 个 `useState`，每个都是"界面要记住的一件事"：当前标签、审批列表、是否在线、模型状态、弹窗开关、演示视角……

**③ 副作用**（90–140 行）
- 挂载时 `probe()`：连上就拉真数据，连不上就保持假数据。
- 定时器每 1.5 秒拉一次任务列表。
- 任务完成数量变化时，顺手刷新事件流和看板。

```tsx
useEffect(() => {
  const t = setInterval(loadTasks, 1500);
  return () => clearInterval(t);      // 组件卸载时清掉定时器
}, [online]);
```

**`return () => clearInterval(t)` 千万别漏**。漏了的话，组件被销毁后定时器还在跑，内存一路涨，这叫**内存泄漏**。

**④ 界面**（250–451 行）
顶栏 → KPI 条 → 三栏（员工 / 工作区 / 审批中心）→ 弹窗。

有几个细节值得注意：

```tsx
const visibleStaff = Object.values(AGENTS).filter(a =>
  (!staff[a.k] || staff[a.k].hired) && (view === '主理人' || staff[a.k]?.owner === view));
```

这是"**数据决定界面**"的典型：切到某个主管视角，员工列表自动只剩他手下的人。没有一句"隐藏 DOM"，全是过滤数组。

```tsx
const visibleApprovals = approvals.filter(a =>
  view === '主理人' || (mode === 'team' && a.risk !== 'red' && staff[a.from]?.owner === view));
```

注意 `a.risk !== 'red'`：**红线事项无论如何都不给主管看**。业务规则直接写在过滤条件里，这就是"代码即制度"。

## 4.5 自定义 Hook：`useRescueFlow` 到底干了什么

```ts
useEffect(() => {
  if (!online || !id) return;
  const poll = async () => {
    const next = await demoApi.read(id);
    setRun(next);
    if (['running','executing','awaiting_approval'].includes(next.status))
      timer = setTimeout(poll, 900);          // 还在跑，900ms 后再问
  };
  void poll();
}, [online, id, epoch]);
```

三个要点：
1. **只在"还在跑"的状态下继续轮询**。到了"待审批"或"完成"就停，不浪费请求。
2. **`localStorage` 记住上一次的 run id**。刷新页面能接回原来那轮，不用重来。
3. **`epoch` 计数器**：手动换一个 run 时让它 +1，强制 `useEffect` 重跑（因为 `id` 可能没变但内容变了）。

这类"细节处理"就是前端经验和新手的分水岭。

## 4.6 `app.css` 与 `tokens.css`：样式是怎么组织的

```

**样式分成两层**：

# 第 5 章 桌面壳（`apps/desktop`）

## 5.1 `main.cjs`：窗口和进程的总管

```js
app.setPath('userData', path.join(app.getPath('appData'), 'AI-Ecom-Company'));
```

这一行决定 `%APPDATA%\AI-Ecom-Company` 这个目录。**所有用户数据、日志都在它下面**，因为 `desktop_entry.py` 会把这个路径传给后端当 `AIECOM_DATA_DIR`。

```js
if (!app.requestSingleInstanceLock()) app.quit();
else app.on('second-instance', () => { win.show(); win.focus(); });
```

**单实例锁**：第二次双击 exe 不会开第二个窗口，而是把已有的叫到前面来。不做这个，用户双击三次就有三个后端在跑，数据互相覆盖。

安全配置这一段是所有 Electron 项目的必修课：

```js
webPreferences: {
  preload: path.join(__dirname, 'preload.cjs'),
  contextIsolation: true,     // 页面和 Electron 内部隔离
  nodeIntegration: false,     // 页面不能直接调 Node（不能读写硬盘！）
  sandbox: true,              // 渲染进程进沙箱
}
```

**为什么这么严**：页面里会显示模型返回的文字。万一有恶意内容，`nodeIntegration: true` 就等于让它能删你的文件。关掉它，页面只能通过 `preload` 暴露的那几个方法做事。

```js
win.webContents.session.setPermissionRequestHandler((_c, _p, cb) => cb(false));
```

默认拒绝所有权限请求（摄像头、定位、通知……）。演示工具不需要这些。

## 5.2 `backend.cjs`：怎么把 Python 拉起来并确认它活着

```js
const port = await freePort();                    // 1. 找一个空闲端口
const instance = randomUUID();                    // 2. 生成一个"身份证号"
child = spawn(python, ['desktop_entry.py', '--port', port, '--web', webDir, '--data', dataDir, '--instance', instance], ...);
while (Date.now() < deadline) {
  if (await health(url, instance)) return {...};   // 3. 每 200ms 敲一次门
}
```

**为什么要 `instance` 这个 UUID**：本机可能同时开着浏览器开发版（8000 端口）。如果只检查"8000 端口有没有人应答"，可能误连到开发版的后端上。带上 UUID，只有**我自己刚起的这个后端**会报出这个 UUID，绝不会认错爹。

这是很典型的"**看起来多余，其实防大坑**"的设计。

## 5.3 `preload.cjs`：只递出去一把钥匙

```js
contextBridge.exposeInMainWorld('desktop', {
  version: () => ipcRenderer.invoke('app:version'),
  notify: (title, body) => ipcRenderer.invoke('app:notify', { title, body }),
  apiBase: process.argv.find(v => v.startsWith('--aiecom-api-base='))?.slice('--aiecom-api-base='.length),
  isDesktop: true
});
```

页面窗口里因此多了个 `window.desktop`，只有 4 个东西。`apiBase` 就是从命令行参数里读出来的后端地址——**这就是前端 `api.ts` 里那个 `window.desktop.apiBase` 的来源**，一条链终于闭合了。

## 5.4 `desktop_entry.py`：30 行，但顺序不能错

```python
os.environ['AIECOM_DATA_DIR'] = str(args.data.resolve())
os.environ['AIECOM_WEB_DIR'] = str(args.web.resolve())
os.environ['AIECOM_DESKTOP_INSTANCE'] = args.instance
os.environ['AIECOM_SKIP_DOTENV'] = '1'

文件第一行注释就说了：**"路径参数必须在导入应用前设置"**。

# 第 6 章 一条完整链路：点"启动救援 · 书生实时分析"之后

这一段是全篇的精华。把这 12 步走通，你就真的懂这个项目了。

**① 你点了按钮**

`RescuePanel.tsx` 里那个按钮绑的是：

```tsx
<button onClick={() => start('live')}>
```

`start()` 调 `flow.start('live', { data, preset, shop_id })`。

**② 前端发请求**

`useRescueFlow.ts` → `demoApi.start(...)` → `api.ts`：

```ts
post('/api/demo/runs', { mode, auto_approve, ...extra })
```

实际发出去的是：`POST http://localhost:8000/api/demo/runs`，body 里带着你编辑过的整套业务数据。

**③ 后端接单**

`main.py` 把 `/api/demo/*` 转给 `competition.py` 的 router，`start()` 函数开始跑。

先做五道检查：

```python
if any(r["status"] in ("running","executing") ...): raise 409  # 已有流程在跑
if body.shop_id != "sandbox" and 店铺不存在: raise 404
for key in ("ceo","cmp"):                                     # 规划和风控岗位必须有人
    if not store.staff[key]["hired"]: raise 409
preset = 找案例; if not preset: raise 422
data = body.data or 案例默认数据                                 # Pydantic 已经校验过数值范围
```

**④ 建一条运行记录**

```python
run = {"id": "DEMO-xxxxxxxx", "status": "running", "node": "sense",
       "before": deepcopy(data), "current": deepcopy(data),   # 关键：两份！
       "trace": [], "receipts": [], "model_calls": [], "checks": [],
       "input_hash": sha256(json.dumps(data, sort_keys=True))[:16],
       "memory": [最近 3 轮同店运行的摘要]}
```

**`before` 和 `current` 是两份独立的深拷贝**——这一行就是"可回滚"的全部秘密。`before` 永远不动，`current` 一步步被改。回滚 = 用 `before` 覆盖 `current`。

**`input_hash`**：把输入数据算成一个 16 位的指纹。用途是"证明这次运行用的就是这份数据"，导出证据时带上，别人无法抵赖。

**⑤ 存盘，然后异步启动**

```python
store.save()                                  # 先落盘，保证断电也能恢复
service.launch(run_id, service.plan_graph)    # 再起后台任务
return service.public(run)                    # 立刻返回，不等它跑完
```

**注意这个顺序和"立刻返回"**：如果接口等整个流程跑完（几十秒）才返回，前端会超时。所以接口只负责"启动"，进度靠前端轮询。这是长任务的通用范式。

**⑥ 后端走流程（六个节点）**

`sense` → `plan` → `review` → `gate`，每个节点做完往 `trace` 里追加一条记录：

```python
self.log(run, "plan", "经营规划 AI", "已生成 3 个工具动作", detail={...})
```

**这就是界面上那条实时日志的来源。**

`plan` 节点里，模型收到的不是"帮我分析一下"这种空话，而是 `decision_context()` 算好的硬约束：

```json
{"inventory": {"minimum_transfer": 120, "maximum_transfer": 480,
               "resources_sufficient": true, "arrival_in_time": false},
 "ads": {"maximum_move": 900}, "service": {"uncovered_damaged_orders": 12}}
```

**把"能调多少"先算好告诉模型，模型只需要在合法范围内做取舍**。这比让它自由发挥可靠一个数量级。

**⑦ 到闸门，停下**

`gate` 节点生成一张审批卡，状态写 `awaiting_approval`，流程**真的停了**。前端轮询发现状态变了，右侧审批中心就多出一张卡。

**⑧ 你在界面上追问 / 通过**

点"通过并模拟执行" → `POST /api/approvals/{id}/decide`。

后端先查权限和状态，然后找到关联的 run：

```python
demo_run = next((r for r in store.demo_runs.values() if r.get("approval_id") == aid), None)
if demo_run:
    if body.approve: store.demo_service.approve_run(demo_run)
```

**⑨ 执行**

`execute` 节点逐个调工具。**每调一个，写一份回执**：

```python
run["receipts"].append({"tool": "inventory.transfer", "arguments": {"quantity": 240},
                        "output": {...}, "at": stamp()})
```

**回执是这个项目最重要的证据**：它证明"确实执行了什么、参数是多少、结果是什么"。答辩时被问"你说执行了，凭什么"，答案就是回执 + trace + 快照。

**⑩ 校验**

`verify` 节点对比前后指标，逐项检查约束（库存不能为负、预算总额不变、工单不超上限）。`checks` 数组里 `passed: false` 的会显示成红色 `!`。

**⑪ 前端轮询看到结果**

900 毫秒后前端再问一次，拿到 `completed`，界面显示：

```
库存覆盖 4 天 → 8 天 · 工单 12 / 48 · 4 项执行校验通过
```

**⑫ 存盘**

每一步结束都 `store.save()`。中途关掉程序再打开，可以从检查点继续。

# 第 9 章 想改东西，该改哪个文件

| 你的需求 | 改哪里 | 难度 | 注意 |
| --- | --- | --- | --- |
| 改界面文字 | `apps/web/src/App.tsx` 等组件 | 低 | 改完刷新页面即可 |
| 改配色 | `packages/ui/tokens.css` 里的 `:root` 变量 | 低 | 只改变量，别改具体元素；深色模式在同一个文件 |
| 加业务案例 | `competition.py` 的 `PRESETS` | 低 | 字段名要对 |
| 调五个案例的数值 | 同上，改 `changes` 字典 | 低 | 注意校验规则 |
| 加一个 AI 岗位 | `apps/api/app/seed.json` 的 `agents` | 中 | 前端会自动多一行 |
| 加会议模板 | `seed.json` 的 `meetings` | 中 | 议程结构较复杂，照抄现成的 |
| 加一个接口 | `main.py` 加 `@app.get/post` | 中 | 记得同步 `api.ts` |
| 改救援流程步骤 | `competition.py` 的 `plan/review/execute` | 高 | 改完必须重跑评测 |
| 加一个新工具（比如改价） | `TOOLS` + `validate_action` + `execute_tool` + `approval_labels` | 高 | **四处都要改，漏一处就出 bug** |
| 把 JSON 存储换成数据库 | **只改 `store.py`** | 高 | 这就是分层的回报 |
| 换模型服务商 | 界面「模型配置」或 `.env` | 低 | 只要兼容 OpenAI 协议就能用 |
| 改打包流程 | `scripts/build-windows.py` | 高 | 别动 |
| 改桌面窗口大小 | `apps/desktop/main.cjs` 的 `width/height` | 低 | 改完要重新打包 |

**一条通用规律**：越靠"配置"的改动越安全，越靠"核心流程"的改动越危险。改 `seed.json` 基本不会出事，改 `competition.py` 的执行逻辑要重跑全部测试和评测。

# 第 10 章 十个新手一定会踩的坑

**1. 改了代码，页面没变**
你改的是 `src`，但打开的是 `dist`。开发模式用 `npm run dev`；打包版必须重新 `npm run build`。

**2. `npm ci` 报错说找不到 package-lock.json**
你在错误的目录。`package-lock.json` 在 `platform/` 根目录，不在 `apps/web/`。

**3. 后端起来了，前端还是"本地演练"**
三种可能：后端端口不是 8000；CORS 没放行你的端口；`probe()` 的 1.5 秒超时了（后端启动慢）。先看 `logs/backend.log`。

**4. `ModuleNotFoundError: No module named 'fastapi'`**
你用了系统的 Python，不是 `.venv` 里的。要用 `apps/api/.venv/bin/python`（Windows 是 `.venv\Scripts\python.exe`）。

**5. 改了 Python 代码，接口没变化**
uvicorn 有热重载，但只对 `--reload` 模式有效。`desktop_entry.py` 没开 reload，所以**桌面版改了后端必须重启应用**。

**6. 模型一直 401**
Key 错了，或者 Base URL 少了 `/v1`。注意 `llm.py` 里会 `rstrip("/")`，所以结尾多斜杠没关系，但路径必须对。

**7. 模型一直超时**
默认超时 60 秒。国内网络调某些服务确实慢。这时不该死等——本项目所有调用都有兜底，会切到规则模式，**这是设计，不是 bug**。

**8. 端口被占用**
`netstat -ano | findstr :8000` 看谁占着。或者在任务管理器里结束那个 python 进程。

**9. 删了 `state.json` 后画面错乱**
如果程序还在运行，它内存里有旧状态，下次 `save()` 又会写回去。**先关程序，再删文件。**

**10. 在压缩包里直接双击 exe**
必崩。Electron 需要读同目录的 `resources`，压缩包内的虚拟目录不支持。**必须先完整解压。**

# 附录 B 三个最该记住的设计

1. **模型只出方案，代码负责执行和校验。**
   模型会算错、会编造、会超时；代码不会。所以"算"的部分用代码，"想"的部分用模型，中间用 Pydantic 和 `validate_action` 卡住。

2. **每个动作都可追溯、可回滚、可复现。**
   `before`/`current` 双份数据 + `receipts` 回执 + `input_hash` 指纹 + 原子写入。这四样凑齐，才有资格说"这是可信的自动化"。

3. **失败路径和成功路径一样重要。**
   模型不通切规则、解析不了回落、校验不过拦截、断点能续跑。一个演示系统能不能上场，取决于它在最糟的情况下会不会当场卡死。
