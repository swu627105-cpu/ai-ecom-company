# AI 电商公司 · 平台使用说明

适用版本：0.1.0（Windows x64 / macOS / Linux 源码）
本文讲**怎么用**这个平台；讲怎么打包、怎么生成 exe 的，请看同目录的 `Windows使用说明.md`。

---

## 一、这是什么

一个"全 AI 员工"的电商公司运营台。你扮演**主理人**，下面有 12 个 AI 岗位（店长、商品、投放、内容、直播、客服、口碑、供应链、履约、财务、数据、合规）。

平台的核心是一条**可执行的经营闭环**：

> 发现异常 → AI 规划 → 独立风控复核 → 你审批 → 跨岗执行（改沙箱数据） → 结果校验 → 录入反馈 → 下一轮

和普通"AI 聊天工具"的区别在于：AI 不只是给建议，它会在你点"通过"之后真的去调拨库存、迁移广告预算、创建售后工单——只不过改的是本地沙箱里的模拟数据，不接任何真实店铺。

**一句话理解边界**：流程是真的，工具是真的，数据是假的。

## 二、启动

### 2.1 便携版（推荐给评委 / 演示现场）

拿到 `AI-Ecom-Company-0.1.0-Windows-x64.zip`（约 178 MB）：

1. 右键压缩包 → **全部解压**（不要只把 exe 拖出来，也不要在压缩软件里直接双击）。
2. 把整个文件夹放到一个固定位置。
3. 双击 `AI-Ecom-Company.exe`（或 `Start-App.cmd`）。
4. 首次启动会等待本地服务就绪，随后自动打开运营台。

不需要装 Node.js、Python，也不用开终端。程序用随机本地端口，和源码浏览器版互不干扰。重复双击会激活已有窗口，不会开出第二个后台。

想放到桌面：双击 `Create-Shortcut.cmd` 生成快捷方式；指向当前解压位置，之后别单独搬走这个文件夹。

> 该程序未做代码签名，Windows 可能提示"未知发布者"。属于正常现象，点"更多信息 → 仍要运行"。

### 2.2 源码浏览器版（开发、调试用）

前提：Node.js 22 LTS 以上 + 64 位 Python 3.11 以上（建议 3.13）。

```powershell
# 双击 scripts\windows\Start-Local.cmd 即可
# 或手动：
npm ci
.\scripts\windows\Start-Local.ps1
```

- 前端：`http://localhost:5173/`
- 后端：`http://127.0.0.1:8000/`
- 终端要一直开着；`Ctrl+C` 关闭的是这个脚本起的服务。
- 首次安装依赖需要联网。

常用参数：

```powershell
.\scripts\windows\Start-Local.ps1 -SkipInstall   # 依赖已装好，跳过安装
.\scripts\windows\Start-Local.ps1 -NoBrowser     # 不自动开浏览器
.\scripts\windows\Start-Local.ps1 -Desktop       # 起源码桌面版
```

macOS / Linux 用 `bash scripts/start-local.sh`。

### 2.3 源码桌面版

双击 `scripts\windows\Start-Desktop.cmd`：自动装依赖、构建前端、起桌面窗口，后端由桌面进程托管。

注意：**源码桌面版和浏览器版的数据是分开的**，两边看到的运行历史不一样。

### 2.4 启动后先自检（可选）

在便携版解压目录打开 PowerShell：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Smoke-Test.ps1
```

它会用独立临时目录跑一遍：Python 可用性、时区、前端页面、规则规划、人工批准、业务执行、回滚。看到 `PASS` 就说明骨架没问题（不验证模型网络连通和窗口交互）。

## 四、第一次使用：配置模型

点顶部 **模型配置**：

| 字段 | 填什么 |
| --- | --- |
| Base URL | 默认 `https://discovery-api.intern-ai.org.cn/v1`，换服务商时改这里 |
| API Key | 你自己的书生 Key，`sk-...` |
| 模型 | 默认 `intern-s2`；测试连接后这里会列出你的 Key 可用的模型 |

1. 点 **测试连接**——成功会提示"可用模型 N 个"。
2. 点 **保存并应用**。

几点说明：

- Key **只存在本机后端**（`settings.json`），不会回传到前端页面。
- 已保存过 Key 时输入框留空 = 不修改。
- 保存后仍连不上也没关系：会议会自动回落到规则话术，救援可以走"规则策略演练"，不会卡死。
- 想清除 Key：直接在配置文件里删掉对应字段并重启后端。

## 五、核心流程：大促经营救援

入口：**公司频道** → 顶部就是「大促经营救援」面板（也可以点顶栏"经营救援演示"）。

### 第 1 步：选业务案例

"业务案例"下拉里五个预设（下方的"五个内置案例"有对照表）。选完会**自动填充**一整套业务数据。

### 第 2 步：编辑本轮业务数据（可选）

展开「编辑本轮业务数据 / 导入 JSON」，可以逐个字段改数字。

**库存**

| 字段 | 含义 |
| --- | --- |
| 店铺库存 / 件 | 当前可售库存 |
| 日均销量 / 件 | 近 7 天日均 |
| 常规交期 / 天 | 主供应商补货天数 |
| 备用仓库存 / 件 | 可调拨上限 |
| 调拨交期 / 天 | 从备用仓调过来要几天 |
| 调拨单价 / 元 | 每件调拨成本 |

**广告**：拉新预算、复购预算、拉新 ROI、复购 ROI、保本 ROI

**售后**：订单总数、退款订单、破损订单

**财务**：可用现金 / 元

两条容易踩的规则：

- 广告预算 = 广告账户里**已经预付**的额度；可用现金只用于调拨。两个池子分开算，别互相挪用。
- 提交时的校验：`破损单 ≤ 退款单 ≤ 总订单`，`工单数 ≤ 破损单数`，`拉新+复购预算 > 0`。不满足会直接拦下来并提示具体哪一条。

想批量改：点 **下载本轮数据** 拿到 JSON，改完再 **导入业务 JSON**（≤1 MB，必须包含全部数字字段和 `service.tickets` 数组）。

"模拟店铺"下拉可以切换店铺。**每轮运行保存独立快照，店铺之间历史和上下文互相隔离**——这是有意的设计，别指望 A 店执行的结果影响 B 店。

### 第 3 步：启动

两个按钮，选一个：

| 按钮 | 做什么 | 什么时候用 |
| --- | --- | --- |
| **启动救援 · 书生实时分析** | 真实调用模型做规划 + 独立风控复核 | 演示、验收、想看真实模型能力 |
| **规则策略演练** | 纯本地确定性算法，**不调用模型** | 没 Key、断网、只想快速看流程 |

规则模式会明确标注"规则策略 · 未调用模型"，不会拿规则冒充模型结果。

### 第 4 步：看六个阶段

启动后顶部会出现阶段条：

> 发现异常 → 书生规划 → 风控复核 → 主理人审批 → 跨岗执行 → 结果校验

走完的打勾，正在跑的加粗。下面实时显示最近两条 trace（谁、做了什么）。这时候**不要重复点启动**——同一时刻只允许一个运行在跑。

展开「查看联合方案」能看到：结论、发现、每个工具动作的参数和理由、风控意见。

### 第 5 步：审批（最关键的一步）

状态变成 **联合方案待审批** 时，方案已经推进**右侧审批中心**了。

在审批卡上你能做四件事：

1. **看决策依据**——结论 / 数据 / 理由 / 风险 / 回滚方式 / 出处，六段全给。
2. **向书生追问**——比如"为什么采用这个方案？最主要的风险是什么？"，回答会挂在卡片下面。
3. **退回修改**——写清修改要求（"请降低资金占用并重新核对交期"），点"退回并重新规划"。旧方案和旧审批会保留，新版本重新过一遍模型和风控。
4. **通过并模拟执行** / **驳回**。

> 高风险联合方案永远需要人工批准。L1 岗位只能建议，L2–L4 才是"批准后执行"。

### 第 6 步：执行与校验

批准后后端会真的跑工具：

| 工具 | 效果 |
| --- | --- |
| `inventory.transfer` | 从备用仓调拨，扣库存额度、扣现金、累计调拨费 |
| `ads.rebalance` | 拉新→复购迁移预算，总额不变，单次上限 900 元 |
| `service.create_tickets` | 给未建单的破损单创建排查工单 |

看结果的两个地方：

- 面板里的「沙箱业务指标」：执行前 → 当前，对比库存覆盖天数、预算加权 ROI、工单数。
- **任务**标签页：每个任务有进度条、逐步执行记录、工具回执。卡片上的标签区分 `沙箱工具执行`（真改数据）和 `步骤演示`（只是演示步骤，不动数据）。

底部还会列出**约束校验记录**，`✓` 通过、`!` 未通过，鼠标悬停看详情。

### 第 7 步：录入反馈，进入下一轮

状态到 **救援完成 · 结果已验证** 后，展开「录入模拟反馈」：

| 字段 | 说明 |
| --- | --- |
| 窗口发货件数 | 一个观察窗口里实际发出去多少 |
| 下一轮预测日销 | 用来推算下一轮库存覆盖 |
| 拉新消耗 / 拉新归因 GMV | 用来算**模拟观察窗口 ROI** |
| 复购消耗 / 复购归因 GMV | 同上 |
| 已解决工单数 | 工单处理量 |

- 消耗填 0 表示"这轮没观察"，保留原 ROI，不会算出 0 除。
- 观察窗口 ROI 和 KPI 上的"预算加权 ROI（静态估算）"**是两个口径**，故意分开显示，不要混着讲。
- 历史退款率**不会**因为工单关闭而下降——这是刻意的，不虚构改善。
- 保存后点"基于反馈启动下一轮分析"，会带着上一轮上下文开新一轮。

### 配套的四个能力

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 运行历史 | 面板底部「运行历史 · N 轮」 | 点任意一轮切回去看，旧轮次数据都在 |
| 时间回放 | 面板底部「按时间回放本轮记录」 | 播放 / 1×2×4× 变速 / 拖动进度条。**只回放已存记录，不重跑模型、不重放工具** |
| 证据导出 | 「导出证据」 | 下载 `<运行ID>.json`，含完整输入输出、trace、回执 |
| 恢复与继续 | 「从检查点继续」/「恢复执行前快照」 | 见下 |

**中断了怎么办**：状态是 `本轮运行失败` 或 `服务重启，运行已中断` 时，点「从检查点继续」，会从最后一个检查点往下跑（游标机制，不会重复提交已经执行过的工具）。

**想反悔**：点「恢复执行前快照」，库存、预算、现金、工单会回到执行前的完全一致状态，界面提示"快照已恢复"。任务列表里的单条任务也可以点「回滚」。

## 六、五个内置案例

| 案例 | 数据特征 | 想让你看到什么 |
| --- | --- | --- |
| **大促联合救援** | 库存紧、拉新亏损、有破损单 | 三个岗位同时出手：调拨 + 迁预算 + 建工单 |
| **库存告急** | 库存 120、日销 40、交期 6 天 | 覆盖 3 天 vs 交期 6 天，先算缺口再决定调多少 |
| **广告亏损** | 拉新 ROI 1.8、复购 4.8、保本 3.5 | 识别"该把钱从哪挪到哪"，而不是简单砍预算 |
| **退款异常** | 退款 80 单、破损 48 单 | 破损占比高≠破损是根因，只能提排查不能下定论 |
| **资金不足 · 风控拦截** | 可用现金仅 100 元 | **故意让你看到被拦住**——资源不够时风控会拦下方案，你可以补充现金后"退回修改"重算 |

最后一个案例特别值得演示：它证明系统会拒绝，而不是无脑生成方案。

## 七、AI 员工与组织设置

点顶栏 **员工库 / 店铺**。

### 12 个岗位

| 岗位 | 职责 |
| --- | --- |
| 经营 | AI 店长 · 目标拆解与调度 |
| 商品 | AI 商品与价格 |
| 投放 | AI 广告投放与预算 |
| 内容 | AI 短视频 / 笔记 / 直播脚本 |
| 直播 | AI 直播场控 |
| 客服 | AI 售前与售后 |
| 口碑 | AI 评价与口碑 |
| 供应链 | AI 预测 / 补货 / 采购 |
| 履约 | AI 订单 / 仓储 / 物流 |
| 财务 | AI 对账 / 利润 / 现金流 |
| 数据 | AI 流量 / 商品 / 归因 |
| 合规 | AI 平台规则 / 广告法 |

### 三种设置

- **组织模式**
  - `全 AI 运营 · 主理人审批`：所有事都到你手上，视角固定在主理人。
  - `人机协作 · 主管分管`：出现"演示视角"下拉，可切到某位主管；常规事项路由给员工负责人，**红线联合方案仍然只归主理人**。
- **雇佣与分配**：勾掉"已雇佣"该岗位就不参会、不参与规划和执行；"分配给"填主管名，留空是待分配。
- **自治等级**
  - L1 · 仅建议，不执行
  - L2 · 有限自治
  - L3 · 高度自治
  - L4 · 全自治（红线仍需审批）

> 这里的"身份"是本地演示身份，不是生产登录/多租户权限体系。演示时别说成"我们有完整的权限管理"。

## 八、店铺授权（模拟）

同一个弹窗的「店铺授权」标签：

1. 选平台：淘宝/天猫、抖音、拼多多、其他。
2. 填店铺名称 → **添加模拟店铺**。

- 不会跳转外部平台、不会拉真实数据、不会执行真实操作。
- 在公司频道选中某店铺后，各轮运行保存独立数据 + 同店历史上下文。
- 移除店铺只是从列表里删掉，不影响已生成的运行记录。

## 九、召集会议

点顶栏 **召集会议**，三步走：

1. **选模板**：双 11 大促作战会 / 退款率异常复盘会 / 新品首发定价会 / 临时会（自定义议题）。
2. **选参会 AI**（至少 2 人）：未参会者只出书面意见，不参与表决。自定义议题必填。
3. **开始会议** → 逐条议题发言，可"暂停发言"、1×/2×/4× 变速。

会议过程中你可以：

- 在底部输入框随时**插话**（补充意见或直接给方案，回车即发言）。
- 点某个选项**拍板**——拍板权只在主理人，AI 只提供依据。
- 不想听了点 **跳到结论**。
- 结束后 **派发行动项**：每条行动项会变成审批中心里的一张卡片，走正常审批流程。

议程发言是明确标注的规则/模板生成；你现场说的话可以走模型。

会议纪要 + 完整发言会归档到「历史审计」标签。

## 十、分析 标签页

「分析」→ 点 **让书生分析**：把近 7 天订单、退款、评价、投放数据交给模型，输出：

- 一句话结论
- 关键发现（列表）

## 十一、评测 标签页

跑**可复现对照评测**，同一批 5 个合成案例（联合救援、库存、投放、退款、资金不足）比三种方案：

| 按钮 | 跑什么 |
| --- | --- |
| 运行规则基线 | 只跑规则策略，快 |
| 书生三组对照评测 | 规则策略 / 书生单模型 / 书生规划+风控，连续调用模型，**可能要几分钟** |

结果表：正确结果数、异常数、平均耗时；下面还有逐案例明细（可执行/被拦截、失败原因、未通过的校验项）。

- 中途可以 **停止后续案例**（已跑的保留）。
- **导出评测证据** 得到 JSON，可以直接放进答辩材料。
- 表里会标注"网关报告 N tokens"，若网关没给计量会明确写"未提供计量"——不要自己估。

> 样本只有 5 个，只能说"在本数据集上的表现"，不能推断"模型优于规则"或"能带来真实收益"。

## 十二、历史审计

「历史审计」标签 = 会议记录 + 操作审计。

- **会议记录**：每场会议的议题、参会人、逐条发言、你的现场意见、决议、是否已派发。

## 十四、常见问题

**打开就是"本地演练"（黄点）**
后端没起来。看 `logs/backend.log`；源码版确认 8000 端口没被占；便携版确认是**完整解压**后再启动，不要单独运行包内 `resources/python/python.exe`。

**模型一直"未连通"**
三种可能：Key 失效 / Base URL 写错 / 网络不通。点模型标签看具体报错。不影响演示——用"规则策略演练"。

**点了启动没反应**
检查是不是已有一个运行在跑（按钮会变灰并显示当前状态）；或模板还没加载完。

**审批卡不出现**
方案可能先被风控拦了（状态"方案被风控拦截"），先在面板里看拦截原因，用"退回修改"补充资源重算。

**执行后数字没变**
任务卡若标着 `步骤演示`，那只是演示步骤、不改数据。只有 `沙箱工具执行` 才真改。

**反馈保存后 ROI 没变**
消耗填了 0 就是"未观察"，按设计保留原值。

**能不能连我真实的淘宝店？**
不能。店铺授权、库存、广告、售后全部是模拟。这是当前版本明确的能力边界。

## 十五、使用约定（演示时请照这个口径说）

1. **数据是合成的**。五个案例、演示店铺、执行记录都是模拟经营材料，不是真实商家成绩。
2. **模型调用是真的**。规划与风控是真实书生 API；规则模式会明说"未调用模型"。
3. **业务动作改的是本地沙箱**，不接外部店铺 ERP。库存调拨、预算迁移、售后工单都是即时模拟入库。
4. **不声称收益**。ROI 是静态估算或模拟观察窗口值，历史退款率不因工单关闭而改善。
5. **不公开隐式思维链**。给出的是结构化结论、依据和风险，不是模型的内部推理过程。
6. **身份是演示身份**。没有生产登录、租户隔离和生产级权限系统；存储适用于本地单进程演示。
7. **旧提案仍是步骤演示**。价格、采购、文案这类通用提案只走演示步骤，不要当成"已实现价格执行器"来答辩。
