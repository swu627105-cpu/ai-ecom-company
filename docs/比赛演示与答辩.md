# AI 电商公司比赛演示

项目定位：基于书生与LangGraph的可审计电商经营智能体。针对用户提供的赛题，建议以方向3「开放赋能智能体」组织材料。最终参赛信息以赛事要求为准。

## 现场演示顺序（原运营台）

1. 打开 `http://localhost:5173/`。保持原员工、频道和审批三栏，点击「经营救援演示」。
2. 选择「资金不足 · 风控拦截」，启动「书生实时分析」。展开输入字段与模型返回，说明模拟库存240、日销60、交期7天，但现金仅100元。程序不会把资源不足的方案放行。
3. 待风控拦截，展开「编辑本轮业务数据」，将可用现金改为1000元。在修改要求中说明资金来源为模拟注资，提交重做。展示失败版本和新版方案，旧审批不能批准。模型仍可能出错，保留失败记录并根据明确约束再修订。
4. 在原右侧审批中心看依据或追问，批准通过复核的新版。原任务标签记录本地工具回执。库存与预算改变，工单实际创建，历史退款率保持原值。
5. 在频道录入一个模拟观察窗口，例如发货60件、下一轮预测日销70、拉新消耗1000/GMV2000、复购消耗500/GMV2500、解决10笔工单。反馈有明确来源，不冒充真实经营收益。
6. 点击基于反馈启动下一轮。书生根据剩余备用库存、现金和新ROI重新规划，只处理仍有需要的业务。如果资源不足，继续拦截并指出缺口。
7. 展示版本、时间回放、证据导出与恢复执行前快照。回滚只作用于选中运行，后续运行是独立快照。

网络不稳定可选择「规则策略演练」，界面明确标记未调用模型。启动、复核、审批与执行的耗时不做现场固定承诺。

## 技术与证据

- 真实书生调用：经营规划和独立风控两个角色。程序给出确定性计算上下文，模型选择参数并解释依据。
- LangGraph：规划链与执行循环。人工审批、版本与恢复由应用状态管理。
- 白名单工具：`inventory.transfer`、`ads.rebalance`、`service.create_tickets`。规划后和执行前再次检查权限与参数。
- 执行校验：库存覆盖、广告总预算、工单覆盖、预算加权ROI不下降、库存与现金守恒。调拨还检查备用仓到达时间和岗位授权。
- 纠错：JSON错误一次修正、语义约束一次重新规划、请求异常一次重试。失败尝试不删除，不改标为规则成功。
- 反馈：模拟订单出库、ROI观察窗口和工单状态进入下一轮，原执行结果和校验记录保留。
- 恢复：原子JSON文件、工具游标与回执一起提交。重启后明确中断，人工恢复从下一步继续。
- 复现：输入指纹、模型结果、计量信息、工具回执、版本、前后快照与测试记录。

不能宣称已实现MCP、A2A、OpenClaw、GUI智能体或完整长期记忆。平台岗位库与本闭环实际参与的模型角色应区分。

## 实际评测口径

固定5个合成案例，相同输入分别运行规则、单模型和规划风控三组。前三类异常和联合案例应生成满足约束的方案，资金不足应被正确拦截。API/格式错误不能算正确拦截。所有组都保留工具安全边界，不故意让单模型执行危险动作。

首轮真实结果保存在 `demo-evidence/书生对照评测-首轮.json`：规则5/5，单模型3/5，规划风控2/5，包含超时、算术和参数问题。

加入计算上下文与有记录的纠错后，第二轮 `EVAL-45dec317`：

| 方案 | 正确结果 | 请求错误 | 平均耗时/案例 | 实际模型返回 |
| --- | --- | --- | --- | --- |
| 规则 | 5/5 | 0 | 0.010秒 | 0 |
| 书生单模型 | 5/5 | 0 | 16.514秒 | 5 |
| 书生规划加风控 | 5/5 | 0 | 33.299秒 | 10 |

这是一次小样本复测，不能据此宣称模型优于规则。规则在已知简单场景中最快，模型的价值需要通过新的业务约束、自然语言需求和更多案例继续验证。风控组增加一次独立审核，当前样本未测出完成率提升，同时带来额外耗时。网关报告的token数保存在导出记录，不用未知价格换算费用。

自动测试验证软件行为，与上述真实API评测分别记录。当前有46项通过，见 `demo-evidence/流程行为测试.xml`。

## 三分钟讲述

开场约20秒：电商库存、投放、售后各有报表，但跨岗位操作需要一个能保留人工拍板、看见证据并能恢复的执行流程。

接下来约90秒：启动书生分析，展示真实输入。说明资源不足时如何拦截，修改模拟现金后查看新版方案，在原审批中心批准。

接下来约40秒：核对工具回执和实际沙箱变化，录入反馈，展示下一轮以新数据重算。模型等待时间可用于讲解边界与回滚。

最后约30秒：展示可复现评测、失败案例和第二轮改进。说明尚无真实商家收益结论，下一步用授权脱敏样本外测。

## 本地启动与交付

```sh
bash scripts/start-local.sh
```

若已有虚拟环境但缺依赖，执行：

```sh
apps/api/.venv/bin/python -m pip install -r apps/api/requirements.txt
```

验收：

```sh
apps/api/.venv/bin/python -m pytest apps/api/tests -q
npm run build
python3 scripts/export-evidence.py
```

交付时只包含源码、依赖锁文件、测试、文档、合成案例和非敏感证据。排除 `.env`、`apps/api/data/settings.json`、虚拟环境和node_modules。评委使用自己的书生API Key在界面配置。

## 仍需团队补充的参赛材料

团队名称、成员与分工、联系方式、商家授权和真实脱敏样本必须由团队提供。不能代填虚构身份、商家案例、用户规模或收入。最终PPT与录屏应使用本次实际平台和如实注明的评测结果。

最后的浏览器验收额外暴露了风控交期误判和修订时常规交期与调拨交期混淆。当前版本把确定性试执行结果提供给复核角色，对全通过但模型否决的分歧只核验一次，仍否决则停止；原始模型输出与程序裁决分别保留。第二轮批量评测在这项改动之前完成，完整最终版本以浏览器流程证据为准。
