# 演示视频录制脚本

> 目标：4 分钟讲清"这家 AI 公司为什么值得信"。
> 原则：**画面只证明三件事**——AI 真的在干活、人真的能拦住、错了真的能退回去。其余一律剪掉。

---

## 零、开机录像前必须先处理的三个问题

我在你这台机器上查到的情况，不处理会直接毁掉素材。

### 问题 1：便携版没有模型密钥（最关键）

- 便携版的数据目录 `%APPDATA%\AI-Ecom-Company\data\` 里**只有 `state.json`，没有 `settings.json`**。
- 而桌面版启动时会设 `AIECOM_SKIP_DOTENV=1`，**不读源码里的 `.env`**。
- 结论：现在点「启动救援 · 书生实时分析」会立刻报 **「未配置书生 API」**。

**处理**：打开 APP → 顶栏「模型配置」→ 把 `platform/apps/api/.env` 里那把 Key 复制进去 → 点「测试连接」→ 看到"可用模型 N 个"→「保存并应用」→ 确认顶栏标签变成 `模型 intern-s2`（不是"模型未连通"）。

> 这一步**在开录之前做完**。录的时候不要出现输入密钥的画面。

### 问题 2：现在有一轮失败记录

`state.json` 里躺着一条 `DEMO-...` ，状态是 **failed**（就是上面那次没配 Key 导致的），另外还有 2 场会议、2 个任务、15 条频道消息。

一打开 APP，公司频道最上面就是这轮失败的记录，历史里也全是脏数据。**观众第一眼看到的不能是失败。**

**处理**（先备份）：

```powershell
# 1. 完全退出 APP
# 2. 备份并重置
Rename-Item "$env:APPDATA\AI-Ecom-Company\data\state.json" "state.json.bak"
Rename-Item "$env:APPDATA\AI-Ecom-Company\data\settings.json" "settings.json.bak"   # 如果已有
# 3. 重新打开 APP
```

注意：`settings.json` 改名后要重填 Key，所以**顺序是「先配 Key，再重置 state，最后开录」**——或者干脆只删 `state.json`，保留 `settings.json`。

重置后应该看到：审批中心 2 张预置卡、历史 0 轮、频道 5 条初始消息。**这才是干净的片头。**

### 问题 3：别用源码浏览器版录

`apps/api/.venv` 是在 macOS 上建的（里面是 `bin` 不是 `Scripts`），在 Windows 上跑不起来。要用浏览器版得先重建虚拟环境。

**用便携版 exe 录**：双击 `release\AI-Ecom-Company-Windows-x64\AI-Ecom-Company.exe`。

## 一、录制环境清单

| 项目 | 设置 | 为什么 |
| --- | --- | --- |
| 分辨率 | 1920×1080，窗口最大化 | 提交平台基本都要求 1080p |
| Windows 缩放 | **100%** | 125%/150% 会让界面字发虚，压片后更糊 |
| 录屏软件 | OBS Studio（免费）或 剪映自带录屏 | Win+G 码率太低，字会糊 |
| 帧率 / 码率 | 30fps / 8000–12000 kbps | 界面演示不需要 60fps，码率够字才清 |
| 麦克风 | 有线耳麦或领夹麦 | 笔记本内置麦有回声和风扇声 |
| 通知 | 关微信、关系统通知、开"专注助手" | 一条弹窗就得重录 |
| 输入法 | 切到英文 | 中文候选框会挡住按钮 |
| 桌面 | 隐藏图标、换纯色壁纸 | 画面干净，观众只看界面 |
| 鼠标 | 系统设置里调慢一点 | 后期好剪，也不显得慌 |

**试录 15 秒**：回放听有没有回声、看字清不清楚、看鼠标有没有卡顿。这三样任意一样不合格，重设，别硬录。

## 二、4 分钟标准版分镜

时间码按成片算。每个镜头都写清"画面 / 你做什么 / 你说什么"。

### 00:00–00:12 片头（可用标题卡，不用露脸）

**画面**：运营台全貌，鼠标不动，让三栏结构完整入画。
**旁白**：
> "这是一家没有人的电商公司。12 个 AI 岗位，每天自己巡检、自己提方案。而它们的老板——也就是你——每天只需要做一件事：拍板。"

### 00:12–00:40 全景：先让人看懂"这是一家公司"

**操作**：鼠标从左到右缓慢划过三栏（AI 员工 → 公司频道 → 审批中心），最后停在审批中心那两张卡上。
**旁白**：
> "左边是员工，12 个岗位，从选品到供应链到合规。中间是公司频道，它们在这里汇报。右边是审批中心——所有需要花钱、需要改数据的事，都会堆在这里等一个人点头。"

**要点**：这一段不要念岗位名字，观众记不住。只说"12 个岗位"。

### 00:40–01:05 选案例：证明"不是写死的剧本"

**操作**：展开「编辑本轮业务数据 / 导入 JSON」→ 用鼠标快速滑过库存、广告、售后、财务四组字段（不要逐个念）→ 收起来。
**旁白**：
> "数据是可以改的。库存、日均销量、交期、两个广告计划的 ROI、保本线、退款和破损单数、可用现金——十九个字段。改完，这一轮就按新数据重算，不套用任何历史数字。"

**要点**：这一句"不套用历史数字"很重要，它是这套系统和"演示动画"的分界线。

### 01:05–01:35 启动：AI 真的在干活

**操作**：业务案例选「库存告急」→ 点「启动救援 · 书生实时分析」→ 让镜头**完整停留**在六阶段条和实时日志上。
**旁白**（在等待时讲，不要冷场）：
> "现在它自己走：发现异常、规划、独立风控复核。注意这一步——风控是**另一个模型调用**，专门负责挑自己的毛病。"

**画面重点**：`sense → plan → review` 依次点亮、日志里出现"正在调用书生模型…"。
**后期**：这段真实耗时可能 20–60 秒，剪到 25 秒左右，1.5× 加速，但**保留"正在调用书生模型"那一帧**——那是真调用模型的证据。

### 01:35–02:10 审批：这是全片最重要的一段

**操作**：状态变成「联合方案待审批」→ 到右侧审批中心 → 点开「看决策依据」→ 缓慢滚动六段（结论 / 数据 / 理由 / 风险 / 回滚 / 出处）→ 停 1 秒。
**旁白**：
> "方案不是一句话。它必须交出六样东西：结论、支撑数据、判断理由、它自己认为的风险、**失败怎么退回去**，以及每条数据从哪来的。少一样，这张卡就不能过。"

**操作**：展开「追问 AI」→ 用默认问题「为什么采用这个方案？最主要的风险是什么？」→ 点「向书生追问」→ 等答案出来，停留 2 秒。
**旁白**：
> "不放心可以当场问它。它只能拿这张卡里的证据回答，不能编。"

### 02:10–02:40 执行：从"说"到"做"

**操作**：点「通过并模拟执行」→ 切到「任务」标签 → 展示进度条与步骤 → 滚到工具回执 → 回公司频道看「执行前 → 当前」的指标对比。
**旁白**：
> "批准之后才会动手。三个工具：从备用仓调拨、把拉新预算挪到复购、给破损单建排查工单。每个动作都留一份回执——调了多少件、花了多少钱、什么时间。上面这行是执行前后的对比：库存覆盖从 3 天变成 7 天。"

**要点**：一定要让"执行前 → 当前"这一行入画，这是唯一能让观众"看见"结果的画面。
（「库存告急」这个案例按规则算是 3 天 → 7 天；如果走书生实时分析，数字可能略有不同，**旁白就照屏幕上的实际数字念**，别提前背死。）

### 02:40–03:10 高潮：它敢拒绝你

**操作**：回上面，业务案例切到「资金不足 · 风控拦截」→ 启动（这次可以选规则演练，更快）→ 等它显示「方案被风控拦截」→ 停住不动 2 秒。
**旁白**：
> "换个案例。这家店只剩 100 块现金，但它需要调 240 件货。它不会硬凑一个方案，它会告诉你：资源不够，这单做不了。"

**要点**：这是全片最容易被记住的 30 秒。**千万不要剪掉"被拦住"这个结果**，很多人只敢放成功的演示，反而显得假。

### 03:10–03:35 可追溯：能翻旧账、能退回去

**操作**：展开「运行历史」→ 点刚才那一轮 → 点「导出证据」→ （画面切到已打开的 JSON，滚两屏 trace）→ 回来点「恢复执行前快照」→ 指标复原。
**旁白**：
> "每一轮都能导出完整证据：每一步谁做的、输入是什么、输出是什么、模型的原始返回。想反悔，一键恢复执行前的快照，库存、预算、现金、工单，逐项还原。"

**要点**：JSON 不要逐行念，让它滚两屏就够，观众只需要知道"有这个东西"。

### 03:35–04:00 收尾：评测 + 边界

**操作**：切到「评测」标签 → 展示已有那份报告的三行表格（规则策略 / 书生单模型 / 书生规划+风控）→ 鼠标停在"正确结果"那一列。
**旁白**：
> "我们还拿 5 个固定案例做了对照：规则、单模型、规划加风控三组，同一批数据、同一套安全校验。资金不足那个案例，正确答案是被拦住——所以这张表比的不是谁更能干，是谁更少犯错。"

**最后一句（画面停在空白处或标题卡）**：
> "数据是合成的，店铺是模拟的，模型调用是真的。我们不声称能替代运营团队——我们证明的是：AI 动手这件事，可以被管住。"

## 四、录制时的十个坑（都是这个系统特有的）

1. **现场打字**：会卡、会错，还会录进输入法的候选框。所有输入提前填好，或后期加速。
2. **等模型时沉默**：等待段一定要有旁白盖住，否则观众以为卡了。
3. **露出密钥**：模型配置弹窗、`.env`、终端日志，一个都不能入画。
4. **录"书生三组对照评测"**：要跑几分钟，还可能中途失败。用 state 里已经跑好的那份报告。
5. **点"规则策略演练"却说是模型**：这两个按钮旁边会显示"规则策略 · 未调用模型"，说错就翻车。
6. **125% 缩放**：字糊，压片后更糊。必须 100%。
7. **鼠标乱飞**：点击后停 0.3–0.5 秒再移动，后期才剪得干净。
8. **一镜到底**：分镜分段录，每段重录只重录那一段，别整条重来。
9. **忘记关通知**：微信、系统更新、输入法升级提示，任何一个都会毁一条素材。
10. **录完才发现没声音**：每段录完立刻回放 3 秒，确认有声音再往下。

## 五、后期与导出

**剪映 / CapCut 足够，只需要四个操作：**

1. **压缩等待段**：模型调用段 1.25–1.5×，或直接切掉中段（保留开始和结束各 2 秒）。
2. **加字幕**：口播稿单独存一份文本，自动识别后校对——"书生"容易被识别成"书声"，"拍板"容易被识别成"排版"。
3. **点击高亮**：给"通过并模拟执行""恢复执行前快照"这两个关键点击加圆圈或放大。
4. **首尾卡**：首帧放项目名 + 一句话定位；末帧放边界声明（合成数据 / 不接真实店铺）。

**导出参数**：1920×1080、30fps、H.264、8–12 Mbps、AAC 192kbps。
**命名**：`AI电商公司_演示_v1_1080p.mp4`（带版本号，改片不覆盖）。
